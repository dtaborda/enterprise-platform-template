## Critical Rules — Non-Negotiable

### Schema Naming

- ALWAYS: Suffix with `Schema` → `createResourceSchema`, `updateTenantSchema`
- ALWAYS: Prefix with verb for mutations → `create`, `update`, `delete`
- ALWAYS: Suffix query schemas with `QuerySchema` → `resourceQuerySchema`
- NEVER: Generic names like `dataSchema`, `inputSchema`, `formSchema`

### Type Derivation

- ALWAYS: `export type CreateResourceDto = z.infer<typeof createResourceSchema>`
- ALWAYS: Colocate the type export right below the schema
- NEVER: Define a type manually when a schema exists — derive it

### Enum Pattern

- ALWAYS: `const` object + derived type (for runtime + compile-time safety)
- NEVER: Raw string union types without a const source

```typescript
// ✅ CORRECT
export const RESOURCE_STATUS = {
  ACTIVE: "active",
  DRAFT: "draft",
  ARCHIVED: "archived",
} as const;

export type ResourceStatus = (typeof RESOURCE_STATUS)[keyof typeof RESOURCE_STATUS];

export const resourceStatusSchema = z.enum(["active", "draft", "archived"]);

// ❌ WRONG
export type ResourceStatus = "active" | "draft" | "archived";
```

### Dependencies

- ALWAYS: Import only from `zod`
- NEVER: Import from `@enterprise/core`, `@enterprise/ui`, or `@enterprise/web`
- NEVER: Import database types or Drizzle schemas

## Decision Trees

### Where to Put a New Contract

```
Is it a validation schema for input/mutation?
├── Yes → src/dto/{domain}.ts (colocate schema + inferred type)
└── No
    ├── Is it a Zod schema for query params/filters?
    │   └── Yes → src/schemas/{domain}.ts
    ├── Is it a pure TypeScript interface/type (no Zod)?
    │   └── Yes → src/types/{domain}.ts
    └── Is it an enum/const?
        └── Put in the file that uses it most (dto or types)
```

### Where Does This Schema Belong — Here or Elsewhere?

```
Used by Server Actions as input validation?     → HERE (contracts)
Used across 2+ features for type safety?        → HERE (contracts)
Used only by one component for local props?     → KEEP LOCAL (not here)
Generated by Supabase/Drizzle?                  → @enterprise/core or @enterprise/db
```

## Patterns

### DTO Schema (create + update + type inference)

```typescript
import { z } from "zod";

export const createResourceSchema = z.object({
  title: z.string().min(1).max(500),
  type: resourceTypeSchema,
  status: resourceStatusSchema.default("active"),
  description: z.string().max(5000).optional(),
});

export type CreateResourceDto = z.infer<typeof createResourceSchema>;

export const updateResourceSchema = createResourceSchema.partial();

export type UpdateResourceDto = z.infer<typeof updateResourceSchema>;
```

### Query Schema (filtering + pagination)

```typescript
export const resourceQuerySchema = z.object({
  type: resourceTypeSchema.optional(),
  status: resourceStatusSchema.optional(),
  limit: z.number().int().min(1).max(100).default(20),
  offset: z.number().int().min(0).default(0),
});

export type ResourceQuery = z.infer<typeof resourceQuerySchema>;
```

### Const Enum (runtime + compile-time)

```typescript
export const USER_ROLE = {
  OWNER: "owner",
  ADMIN: "admin",
  MEMBER: "member",
  GUEST: "guest",
} as const;

export type UserRole = (typeof USER_ROLE)[keyof typeof USER_ROLE];
```

### ActionResult (standard return type for Server Actions)

```typescript
export interface ActionResult<T = void> {
  success: boolean;
  data?: T;
  error?: string;
}
```

## Rules

1. **Zero internal deps**: Only dependency is `zod`. Never import from `@enterprise/core`, `@enterprise/ui`, or `@enterprise/web`
2. **Schema naming**: Always suffix with `Schema` (e.g., `createResourceSchema`)
3. **Type inference**: Derive TypeScript types from schemas using `z.infer<typeof schema>`
4. **File organization**: DTOs in `src/dto/`, validation schemas in `src/schemas/`, pure types in `src/types/`
5. **Barrel export**: `src/index.ts` re-exports everything — consumers import from `@enterprise/contracts`
6. **Enums**: Define as `const` objects + `z.enum()` for runtime validation AND type narrowing
